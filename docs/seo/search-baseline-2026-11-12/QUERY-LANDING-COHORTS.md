## Method And Limits

Use the same tested self-contained analyser offline and in the existing reporting
session. Fetch only same-origin GET /api/search-console/performance with explicit
baseline dates ending10 November, Web, query/page dimensions and contiguous1000
offsets. Bound requests; stop on any mismatch/duplicate/coverage failure. Do not
call paid SERP, inspection, action-log mutation or configuration endpoints.

Process full-precision rows in temporary function memory. The connector's prior
file-output restriction is not bypassed: do not export raw private URL/query
values or authentication data through another channel. Return only counters,
existing independent property summary, known public query labels and allowlisted
public landing paths. Query-string/fragment variants remain distinct keys before
deliberate labelled path roll-up, with their counts retained. Unknown paths are
redacted, not silently discarded. No provider position/CTR averages are computed.

Reaching the end of returned pagination does not mean all Google search data is
available. Query/page rows use page aggregation and cannot be subtracted from
property totals to infer missing, anonymous or complete nonbrand traffic.
More than one landing page for a query is a review clue, not proven cannibalization,
conversion behavior or migration impact; the retained windows mostly predate
the5 November cutover. No redirect/noindex/canonical action follows automatically.

Primary method references checked14 November:
[Search Analytics query](https://developers.google.com/webmaster-tools/v1/searchanalytics/query)
and [Google Performance report](https://support.google.com/webmasters/answer/7576553?hl=en).
